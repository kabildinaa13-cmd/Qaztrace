# ChainSentra API v2: транзакции

API v2 работает рядом с legacy API и не удаляет существующие маршруты. Цель контракта — одинаковое представление переводов Ethereum, BNB Smart Chain, TRON и Bitcoin без потери сетевой специфики.

## Маршруты

- `GET /api/v2/health` — версия API и схемы.
- `GET /api/v2/networks` — реестр сетей и реально реализованные возможности адаптера.
- `POST /api/v2/networks/detect` — определение кандидатов по формату; `probe: true` дополнительно проверяет активность через live API.
- `GET /api/v2/addresses/:address/transactions?network=ETH&limit=25` — нормализованная история.
- `network=ALL` — объединённая проверка Ethereum и BNB Smart Chain для одного EVM-адреса.

История и live-проверка требуют Bearer-токен. Реестр сетей и health не содержат материалы дела и доступны без авторизации.

## Доказательность

Каждый ответ внешнего провайдера сохраняется в `backend/data/raw_provider_responses/YYYY-MM-DD.jsonl`. Для него вычисляется SHA-256 по каноническому JSON. Нормализованная операция содержит провайдера и время получения, идентификатор и SHA-256 raw-ответа, сеть, блок, время, статус, адреса, точное целочисленное значение и сведения об активе. Для Bitcoin сохраняются все inputs и outputs.

Raw-ответ не считается доказательством личности владельца адреса. Он фиксирует только сведения, возвращённые публичным blockchain-провайдером в момент запроса.

## Пагинация

- EVM использует `page` и `limit`.
- TRON использует непрозрачный `cursor` с отдельными fingerprints нативной и TRC20-истории.
- Bitcoin использует последний txid страницы как `cursor`.

Клиент должен передавать полученный cursor без изменения.

## Bitcoin

Поле `amount` — абсолютный чистый поток для проверяемого адреса. Все inputs/outputs сохранены отдельно. Система намеренно не объявляет output «сдачей» и не связывает его с владельцем без дополнительного подтверждения.

## Ограничения этапа 1

- Декодирование EVM swap/bridge/ABI ещё не выполнено.
- Балансы и активы пока остаются в legacy API.
- Для бесплатных API возможны rate limits; ошибки отражаются в `dataQuality.errors`.
- История EVM зависит от публичного Blockscout/Routescan и может быть неполной для конкретной сети.
