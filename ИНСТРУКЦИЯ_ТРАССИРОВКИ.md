# ChainSentra: трассировка реальных переводов TRON

## Что уже подключено

- Реальная история TRC-20 через TronGrid, а не демонстрационные транзакции.
- Поиск за выбранный исторический период.
- Трассировка USDT/USDC/USDD до шести переходов.
- Полные адреса и хеши транзакций.
- Таблица до 20 конкурирующих переводов после каждого поступления: сумма, задержка, совпадение и уверенность.
- Автоматический поиск схемы «рассеивание → сбор»: несколько прямых получателей переводят средства на один общий адрес.
- Поиск точек выхода по локальной базе меток: биржи, мосты, DEX, платёжные сервисы, миксеры, санкционные и иные известные организации.
- Кандидаты смены USDT/USDC/USDD с отдельным предупреждением, что без разбора смарт-контракта обмен не доказан.
- Расчёт покрытия исходной суммы, непрослеженного остатка и доли, дошедшей до известной организации.
- Разделение результата на факты блокчейна, вероятные связи и ограничения.
- Конечные адреса в пределах проверки и совпадения с локальной базой организаций.
- Копирование понятного отчёта и выгрузка TXT, CSV, JSON и доказательственного пакета с SHA-256.
- Сохранение трассировки в карточку расследования и повторное открытие отчёта.
- Добавление конечных адресов в watchlist и продолжение проверки с любого результата.
- Черновик официального запроса бирже или сервису по адресу, хешам и времени.

## Запуск на Windows

1. Откройте CMD в папке проекта.
2. Один раз выполните:

   ```cmd
   npm install
   ```

3. Запустите `start-windows.bat`. Откроются два окна: API и сайт.
4. При первом запуске скрипт безопасно перенесёт существующий `.env` из прежней папки `Downloads\ChainSentinel (1)\ChainSentinel`, не показывая ключи на экране. Никому не отправляйте `.env` и не публикуйте его.
5. Откройте `http://localhost:5174`.
6. Не закрывайте окна API и сайта, пока работаете.

Ручной запуск вместо файла:

```cmd
set STORAGE_DRIVER=json
set PORT=8787
npm run api
```

Во втором окне CMD:

```cmd
set VITE_API_BASE_URL=http://localhost:8787
npm run dev
```

## Как проверить конкретный перевод 1 960 USDT

Откройте раздел **Трассировка** и заполните:

- Исходный адрес: `TApXXKRdJqTRNhjcn8894Nci75zymcmBEr`
- Токен: `USDT`
- Начало периода: `06.05.2026 00:00`
- Конец периода: не раньше `09.05.2026 23:59`
- Хеш исходной транзакции: `128d234998fd05b49970ad86bfbd260a8d702a68ba50a779b8600ae0b7c329d0`
- Точная сумма: `1960`
- Глубина: сначала `3`, при необходимости до `6`
- Окно следующего перевода: `3 суток`

Нажмите **Построить маршрут денег**.

## Результат проверки на реальных данных

1. **Факт, 100%:** адрес `TApXXKRdJqTRNhjcn8894Nci75zymcmBEr` перевёл 1 960 USDT на `TU4vEruvZwLLkSfV9bNw12EJTPvNr7Pvaa`.
2. Хеш фактической транзакции: `128d234998fd05b49970ad86bfbd260a8d702a68ba50a779b8600ae0b7c329d0`.
3. **Факт блокчейна:** через 3 минуты адрес `TU4vEruvZwLLkSfV9bNw12EJTPvNr7Pvaa` перевёл ровно 1 960 USDT на `TFx6Z24YUQvsP764ntSREBnUM1jK9cqvaj`.
4. Хеш второго перевода: `de26adebc56c7784840d1f56718e2eadcb4dc29cc783d2ed63e9349cc8b9a0dd`.
5. **Связь между поступлением и вторым переводом вероятная, а не доказанная:** уверенность модели 29%. Причина — адрес `TU4v...` очень активный, в окне проверки были десятки поступлений, сотни исходящих операций и другие переводы с похожей суммой.
6. Владелец адреса `TFx6...` по подключённой локальной базе не установлен.
7. В том же окне приложение нашло 15 сильных совпадений и показывает первые 20 кандидатов из 545 исходящих переводов. Поэтому `TFx6...` нельзя считать доказанным единственным конечным получателем.
8. Для этого конкретного перевода подтверждённая точка выхода и схождение нескольких веток в выбранном окне не найдены.

Правильная формулировка для следователя:

> Блокчейном подтверждены два перевода одинаковой суммы с интервалом 3 минуты. Из-за высокой активности промежуточного адреса автоматически установить, что во второй транзакции использованы именно средства первой транзакции, невозможно. Маршрут является версией для дальнейшей проверки, а не доказательством единственного конечного получателя.

## Как проверить схему «нескольким людям, затем одному»

1. Если известна одна конкретная исходная транзакция, укажите её хеш. Если нужно проверить все переводы подозреваемого за период, оставьте поле хеша пустым и максимально сузьте даты.
2. Выберите глубину `3` и достаточное временное окно: сначала `3 суток`, при необходимости `7` или `30 суток`.
3. После проверки откройте раздел **Где несколько веток снова сошлись**.
4. Для каждой точки сбора приложение показывает общий адрес, количество сошедшихся веток, отнесённую сумму, долю исходной суммы и отдельные транзакции, которыми каждая ветка пришла на этот адрес.
5. Нажмите на хеш каждой транзакции и зафиксируйте её в обозревателе блокчейна.
6. Если общий адрес имеет метку биржи или сервиса, подготовьте официальный запрос по адресу, хешам и времени переводов. Только ответ сервиса или другие материалы могут установить физического владельца.

Схождение веток — сильный аналитический признак консолидации, но не автоматическое доказательство миксера или сговора. Все переводы между адресами являются фактами блокчейна; вывод о принадлежности средств к одной исходной сумме после первого перехода остаётся вероятностным.

## Что сохранить в материалы проверки

1. Номер отчёта и время его создания.
2. Полные адреса, суммы, даты и хеши всех переходов.
3. JSON-файл кнопкой **Скачать JSON** — полный машинный отчёт.
4. CSV-файл кнопкой **Скачать CSV** — таблица маршрута и альтернатив для Excel.
5. TXT-файл кнопкой **Скачать TXT** или текст кнопкой **Копировать текст отчёта**.
6. Скриншот таблицы маршрута, точек сбора, конкурирующих вариантов и раздела ограничений.
7. Отдельно зафиксировать, какие переходы отмечены как факт, а какие как вероятные.
8. Нажать **Пакет доказательств** и сохранить файл с контрольной суммой SHA-256.
9. Нажать **Сохранить в дело**, указать сведения о потерпевшем и ущербе в разделе **Расследования**.
10. Для активных конечных адресов нажать **Наблюдать**. Оповещение показывает нового контрагента и его метку, если она найдена в базе.

## Что означает точка выхода

Точка выхода — адрес маршрута, совпавший с известной организацией: например, биржей, мостом, платёжным сервисом или миксером. Совпадение строится по локальной базе меток и всегда показывает её источник и уверенность.

- Нажмите **Скопировать запрос**, чтобы получить технический черновик с адресом, суммами, временем и хешами.
- Нажмите **Продолжить отсюда**, если нужно проверить дальнейшее движение.
- Нажмите **Наблюдать**, если средства ещё могут двигаться.

Перевод на адрес является фактом блокчейна. Название организации является данными подключённой базы и требует проверки источника. Физического владельца аккаунта устанавливают официальным ответом организации и другими материалами дела.

## Как установить реального владельца конечного адреса

Один блокчейн обычно не раскрывает ФИО. Нужен хотя бы один из источников:

- подтверждённая метка биржи, обменника, платёжного сервиса или миксера;
- официальный ответ организации на запрос по адресу и хешу транзакции;
- KYC-данные биржи;
- материалы изъятого устройства, переписки, IP/логов входа или признательные показания.

Совпадение адреса с локальной меткой помогает определить организацию, но само по себе не доказывает личность физического лица или виновность.
